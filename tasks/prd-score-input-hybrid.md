# PRD: Hybrid Score Input Popup (Overlay & Notification)

## 1. Introduction/Overview
사용자가 정기 항해 보고 시간에 맞춰 점수를 입력할 때, 사용자의 설정과 권한 상태에 따라 가장 즉각적인 방법으로 입력 창을 띄웁니다. "다른 앱 위에 그리기" 권한이 있다면 화면 중앙에 즉시 팝업(오버레이)을 띄우고, 그렇지 않다면 중요 알림을 통해 팝업으로 유도합니다.

## 2. Goals
*   **즉시성:** 권한 허용 시 사용자의 개입 없이 자동으로 입력 창을 띄워 접근성을 극대화합니다.
*   **유연성:** 권한이 없거나 사용자가 원하지 않을 경우, 표준 알림 방식으로 자연스럽게 대체(Fallback)합니다.
*   **제어권:** 사용자가 앱 내 설정에서 이 "자동 팝업" 기능을 손쉽게 켜고 끄게 합니다.

## 3. User Stories
*   **사용자로서** 나는 유튜브를 보다가 시간이 되면 자동으로 점수 입력창이 떠서, 터치 한 번으로 점수를 입력하고 다시 영상을 보고 싶다.
*   **사용자로서** 나는 설정에서 "자동 팝업 띄우기"를 켰을 때, 앱이 필요한 권한을 요청해 주기를 기대한다.
*   **사용자로서** 나는 자동 팝업이 부담스러울 때, 설정에서 이를 끄고 일반 알림으로만 받고 싶다.

## 4. Functional Requirements

### 4.1. 설정 UI (`SettingsScreen`)
*   "방해 금지 시간" 아래에 **"팝업으로 바로 띄우기"** 토글을 추가합니다.
*   토글을 **ON** 할 때:
    *   `SYSTEM_ALERT_WINDOW` ("다른 앱 위에 그리기") 권한이 있는지 체크합니다.
    *   없다면 -> 사용자에게 이유를 설명하고 시스템 권한 설정 화면으로 이동시킵니다.
    *   있다면 -> 설정을 저장하고 즉시 활성화합니다.
*   토글을 **OFF** 할 때:
    *   권한 보유 여부와 상관없이 내부 설정값(`pref_use_overlay`)을 `false`로 저장하여 기능을 비활성화합니다.

### 4.2. 오버레이 뷰 (`ScoreOverlayService`)
*   `WindowManager`를 사용하여 다른 앱 위에 떠 있는 뷰(Floating View)를 구현합니다.
*   **디자인:** 앱 내의 점수 입력 다이얼로그와 유사한 디자인을 가집니다.
*   **동작:**
    *   점수 입력 및 저장 -> DB 업데이트 후 뷰 제거.
    *   취소/닫기 -> 뷰 제거.
*   백그라운드에서 실행되어야 하므로 `Service` 컴포넌트로 관리합니다.

### 4.3. 알림 폴백 (`PopupActivity`)
*   오버레이를 사용하지 않거나 권한이 없을 때 실행될 **투명 배경 액티비티**입니다.
*   알림(Notification)을 클릭했을 때 실행됩니다.
*   오버레이 뷰와 동일한 UI/UX를 제공하지만, 기술적으로는 일반 액티비티입니다.
*   종료 시 `finish()` 하여 이전 앱으로 복귀합니다.

### 4.4. 알람 수신 로직 (`AlarmReceiver`)
*   알람이 울리면 다음 순서로 판단합니다:
    1.  설정(`use_overlay`)이 켜져 있고, 권한(`SYSTEM_ALERT_WINDOW`)이 있는가?
        *   **YES:** `ScoreOverlayService`를 시작하여 즉시 팝업 노출.
        *   **NO:** `NotificationHelper`를 통해 알림 발송.
    2.  알림에는 `PopupActivity`를 실행하는 `PendingIntent`를 연결.

## 5. Non-Goals (Out of Scope)
*   오버레이 뷰의 위치 이동(드래그) 기능. (화면 중앙 고정)
*   오버레이 최소화(Bubble) 기능.

## 6. Success Metrics
*   설정에서 오버레이 권한 허용 후, 알람 시간에 유튜브 앱 위로 입력창이 자동 노출됨.
*   설정 해제 후, 알람 시간에 상단 알림 배너가 뜨고 클릭 시 투명창이 뜸.
*   두 경우 모두 입력 후 원래 앱 사용에 지장이 없음.

## 7. Technical Considerations
*   **권한:** `ACTION_MANAGE_OVERLAY_PERMISSION` 인텐트로 설정 화면 이동.
*   **Service Type:** Android 14부터는 포그라운드 서비스 타입 명시가 필요할 수 있으나, 짧은 시간 실행되는 뷰 로직이므로 일반 서비스 또는 `Context.getSystemService(WINDOW_SERVICE)` 호출로 처리 가능 여부 확인 필요. (Service에서 Window 띄우는 건 가능)

## 8. Open Questions
*   오버레이가 떠 있는 동안 뒤쪽 앱(유튜브)은 멈춰야 하는가? -> 아니오, 계속 재생되어야 자연스럽습니다. (`FLAG_NOT_TOUCH_MODAL` 사용)
