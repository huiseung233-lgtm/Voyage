# PRD: 항해 일지(점수 입력) UI/UX 개선 및 시간 표시 기능

## 1. 개요 (Introduction)
본 문서는 Voyage 앱의 '항해 일지(Logbook)' 다이얼로그의 사용성을 개선하기 위한 요구사항을 정의합니다. 기록의 맥락을 파악할 수 있도록 입력 시간을 표시하고, 화면 공간 효율성을 높이기 위해 레이아웃을 재조정하는 것을 목표로 합니다.

## 2. 목표 (Goals)
1.  **기록 시점 가시화:** 사용자가 언제 점수를 획득했는지 알 수 있도록 시간 정보를 제공한다.
2.  **공간 효율 최적화:** 다이얼로그 전체 크기를 줄여 화면 가림을 최소화한다.
3.  **입력 편의성 증대:** '기록된 내역' 영역을 줄이고 '규칙(템플릿) 목록' 영역을 넓혀, 스크롤 없이 더 많은 규칙을 보고 선택할 수 있게 한다.

## 3. 사용자 스토리 (User Stories)
*   **US-1:** 사용자는 내가 언제 이 점수를 기록했는지 알기 위해, 기록 목록에서 '오후 2:30'과 같은 구체적인 시간을 확인하고 싶다.
*   **US-2:** 사용자는 항해 일지 팝업이 너무 커서 답답함을 느끼지 않도록, 전체 창 크기가 좀 더 컴팩트해지길 원한다.
*   **US-3:** 사용자는 점수를 입력할 때 이미 입력한 목록보다는 '입력할 규칙'을 더 많이 보길 원하며, 이를 위해 규칙 목록 영역이 더 넓었으면 좋겠다.

## 4. 기능적 요구사항 (Functional Requirements)

### 4.1 데이터 및 로직 (타임스탬프)
*   **FR-1:** 기존 `ScoreRecord` 데이터 모델에 이미 존재하는 `timestamp` 필드를 활용한다. (DB 스키마 변경 불필요)
*   **FR-2:** `HomeDialogs.kt`의 `LogRecordItem` UI에서 해당 타임스탬프를 `HH:mm` (예: 14:30) 형식으로 변환하여 점수/내용 옆에 표시한다.

### 4.2 UI/UX (다이얼로그 크기 및 레이아웃)
*   **FR-3 (전체 크기):** 다이얼로그의 전체 높이를 기존 `700.dp`에서 약 `500dp ~ 600dp` 수준으로 축소한다.
*   **FR-4 (영역 비율):** 내부 `Column` 레이아웃에서 '기록 내역(상단)'과 '규칙 목록(하단)'의 비율을 조정한다.
    *   *기존:* 상단/하단이 비슷하거나 상단이 큼.
    *   *변경:*
        *   **상단 (기록 내역):** `weight(0.3f)` 또는 고정 높이(예: `150dp`)로 축소. 스크롤 가능해야 함.
        *   **하단 (규칙 목록):** `weight(0.7f)` 등으로 나머지 공간을 대부분 차지하도록 확장.

### 4.3 입력 방식 (기존 유지)
*   **FR-5:** 규칙(템플릿) 클릭 시 O/X 버튼으로 점수 입력하는 방식은 유지한다.
*   **FR-6:** '직접 입력' 팝업의 텍스트/숫자 입력 방식도 그대로 유지한다.

## 5. 제외 사항 (Non-Goals)
*   새로운 데이터 필드(사진, 태그 등) 추가는 이번 범위에서 제외한다.
*   디자인 테마(색상, 폰트)의 전면적인 개편은 제외한다.

## 6. 기술적 고려사항
*   **수정 대상 파일:** `app/src/main/java/com/captain/voyage/ui/home/HomeDialogs.kt`
*   **컴포넌트:** `LogbookContent`, `LogRecordItem`
*   **시간 포맷팅:** `java.time` 패키지 또는 `SimpleDateFormat`을 사용하여 `timestamp` Long 값을 String으로 변환.

## 7. 성공 지표
*   사용자가 스크롤 없이 한 화면에서 기존보다 2~3개 더 많은 규칙을 볼 수 있어야 한다.
*   각 기록 항목에 시간이 올바르게 표시되어야 한다.
