# PRD: Do Not Disturb (Quiet Hours) for Notifications

## 1. Introduction/Overview
현재 주기적인 알림 기능이 구현되어 있으나, 사용자의 수면 시간이나 업무 시간 등 방해받고 싶지 않은 시간대에도 알림이 울릴 수 있습니다. 이 기능은 사용자가 특정 시간 범위(예: 22:00 ~ 07:00)를 "방해 금지 시간(Quiet Hours)"으로 설정하여 해당 시간대에는 알림을 수신하지 않도록 하는 것을 목표로 합니다.

## 2. Goals
*   **사용자 편의성 증대:** 수면 중이거나 집중이 필요한 시간에 불필요한 알림 방지.
*   **유연한 설정:** 자정(00:00)을 넘기는 시간대 설정(Night Shift)을 지원하여 수면 패턴에 맞춤 설정 가능.

## 3. User Stories
*   **사용자로서** 나는 설정 화면에서 "방해 금지 시간"을 켤 수 있다.
*   **사용자로서** 나는 방해 금지 시작 시간(예: 23:00)과 종료 시간(예: 07:00)을 설정할 수 있다.
*   **사용자로서** 설정한 금지 시간 내에 예약된 알람이 있다면, 알림이 울리지 않고 조용히 넘어가기를 원한다.
*   **사용자로서** 금지 시간이 끝나면 다시 정상적으로 알림 주기에 맞춰 알림을 받고 싶다.

## 4. Functional Requirements

### 4.1. 설정 UI
*   `SettingsScreen`의 '정기 보고 알림' 섹션 하단에 **"방해 금지 시간 설정"** 기능을 추가한다.
*   기능을 켜고 끌 수 있는 **스위치(Toggle)**가 있어야 한다.
*   시작 시간(Start Time)과 종료 시간(End Time)을 선택할 수 있는 **TimePicker** UI를 제공한다.
*   현재 설정된 시간 범위가 텍스트로 표시되어야 한다 (예: "23:00 ~ 07:00").

### 4.2. 데이터 저장
*   `SettingsViewModel` 및 `SharedPreferences`에 다음 키를 추가하여 저장한다:
    *   `quiet_hours_enabled` (Boolean)
    *   `quiet_start_time` (String, "HH:mm")
    *   `quiet_end_time` (String, "HH:mm")

### 4.3. 알림 필터링 로직 (`AlarmReceiver`)
*   `AlarmReceiver`가 알람을 수신했을 때, 현재 시간이 "방해 금지 시간" 범위에 속하는지 확인한다.
*   **범위 계산 로직:**
    *   시작 시간 < 종료 시간 (예: 09:00 ~ 20:00): 현재 시간이 두 시간 사이에 있으면 차단.
    *   시작 시간 > 종료 시간 (예: 22:00 ~ 07:00): 현재 시간이 시작 시간보다 크거나, 종료 시간보다 작으면 차단 (자정 통과 케이스).
*   금지 시간 내라면 `NotificationHelper.showNotification()`을 호출하지 않고 로그만 남긴다.
*   **중요:** 알림은 건너뛰더라도, **다음 알람 예약(Reschedule)** 로직은 정상적으로 수행되어야 한다. 그래야 금지 시간이 끝난 후 다음 주기에 알림이 정상적으로 울릴 수 있다.

## 5. Non-Goals (Out of Scope)
*   요일별 방해 금지 시간 설정 (모든 요일 동일 적용).
*   금지 시간 동안 쌓인 알림을 모아서 보여주기 (그냥 건너뜀).
*   긴급 알림(Override) 기능.

## 6. Success Metrics
*   방해 금지 시간을 23:00 ~ 07:00으로 설정하고, 기기 시간을 02:00으로 변경했을 때 알람이 울리지 않음.
*   기기 시간을 08:00으로 변경했을 때 다시 정상적으로 알람이 울림.

## 7. Technical Considerations
*   `LocalTime` 클래스를 사용하여 시간 비교를 수행하면 편리하다. (API 26+ 필수, 현재 minSdk 26이므로 사용 가능)
*   `AlarmReceiver`는 UI 스레드가 아니므로 가벼운 연산만 수행해야 한다.

## 8. Open Questions
*   방해 금지 시간 내에 알람 주기가 너무 길어서(예: 12시간), 금지 시간이 끝난 후에도 한참 뒤에 알람이 울리는 경우는 허용하는가? -> 허용 (단순 Skip 정책).
